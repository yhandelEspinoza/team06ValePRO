# Plan de acceso HTTPS autenticado para la exposición

**Estado actual:** VALPRO en AWS escucha solo en direcciones internas y se accede por SSH. No se abrirán puertos ni se cambiará este estado durante la preparación.

1. Elegir un nombre DNS controlado por el equipo (puede ser un subdominio gratuito con proveedor estable) y asociarlo a una IP estable de EC2, por ejemplo Elastic IP. Comprobar desde la computadora del instituto que resuelve a la IP correcta. Si no hay nombre DNS, evaluar certificado para IP pública solo tras comprobar compatibilidad y vigencia; no improvisarlo el día de la presentación.
2. Preparar un bloque Nginx **separado**, con HTTPS 443, certificado válido y `auth_basic` apuntando a un archivo `htpasswd` fuera del repositorio. Crear credenciales únicas de exposición; almacenarlas fuera de GitHub y comprobar que una solicitud sin credenciales devuelve 401, y con ellas 200. Los recursos estáticos y firmas deben quedar bajo la misma política. El servicio Gunicorn seguirá ligado a `127.0.0.1`.
3. Obtener certificado con Certbot / Let's Encrypt y renovar automáticamente. HTTP-01 exige acceso temporal al puerto 80; DNS-01 permite validar mediante DNS sin abrir 80, si el proveedor soporta automatización. Verificar que el certificado corresponde al nombre y que su renovación funciona. [Validación Let's Encrypt](https://letsencrypt.org/docs/challenge-types/) · [Certbot](https://eff-certbot.readthedocs.io/en/stable/using.html).
4. Antes de cambiar el Security Group, configurar y probar autenticación y TLS con una instancia independiente de prueba. Después aprobar una regla de entrada 443 limitada al público necesario cuando sea posible. No abrir 5000 ni la copia privada actual. [Autenticación básica de Nginx](https://nginx.org/en/docs/http/ngx_http_auth_basic_module.html).
5. Desde el equipo de exposición, verificar inicio de sesión, HTTP 200, siete KPI, cuatro gráficos, filtros, modales, firmas, móvil, tiempo de respuesta y ausencia de errores de consola. Repetir sin credenciales: debe fallar. Confirmar que la URL HTTP no entrega el dashboard y que no hay datos reales visibles sin autenticación.
6. Ensayar una segunda instancia con `VALPRO_DEMO=1` y datos ficticios. Debe mostrar el aviso visible. Mantenerla protegida y separada de la instancia con datos reales. Si falla Sheets, mostrar la demo de forma explícita; no activar datos ficticios silenciosamente.

La autenticación básica sobre HTTPS sirve para una exposición breve; para uso permanente con más usuarios conviene gestión central de identidades y MFA. El acceso público requiere una revisión aparte y autorización previa.
